# Project Development Rules

These instructions are the permanent development rules for this personal cybersecurity portfolio project.

## Engineering Principles

- Write clean, maintainable, reusable code.
- Use TypeScript when application code is introduced.
- Prefer simple, well-scoped solutions; avoid over-engineering.
- Avoid unnecessary dependencies. Add a dependency only when its value clearly exceeds the cost of maintaining it.
- Do not modify unrelated files.
- Do not add features that have not been requested.
- Before making a major architectural change, explain the change and its impact.
- For meaningful changes, run appropriate validation for the project stage, such as linting, type checking, and build checks.

## Design, Responsiveness, and Accessibility

- Prioritize responsive design across desktop, tablet, and mobile.
- Prioritize accessibility, including semantic structure, keyboard navigation, sufficient contrast, visible focus states, and accessible motion behavior.
- Prioritize performance, particularly on mobile and constrained networks.
- Use progressive enhancement: desktop may include richer effects, while mobile must remain lightweight and fully functional.
- Keep animations subtle, purposeful, performant, and mobile-friendly. Respect the user's `prefers-reduced-motion` preference.

## Security and Privacy

- Follow secure development practices throughout planning, implementation, deployment, and maintenance.
- Never expose secrets, API keys, passwords, tokens, private credentials, or private configuration in source code, client bundles, documentation, commits, logs, or screenshots.
- Treat future authentication, database, storage, integrations, and admin features as security-sensitive and design them with least privilege and appropriate access controls.

## Content Integrity

- Do not invent the owner's personal information, achievements, experience, skills, certifications, statistics, employment history, or other biographical claims.
- Use only content supplied or explicitly approved by the owner. If content is missing, leave it unclaimed or ask for it rather than fabricating a placeholder claim.

## Cybersecurity Visual Direction

- Keep cybersecurity-themed visuals professional, original, and relevant to the content.
- Avoid cliché "hacker" aesthetics: Matrix rain, skulls, hacker masks, excessive neon green, fake terminal screens, and meaningless security graphics.
- Favor a premium, restrained visual identity with clean typography, deliberate whitespace, and purposeful technical details.
